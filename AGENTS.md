# Помощник 47 — контекст для ИИ-агентов (Codex, Claude и др.)

Прочитай этот файл целиком перед любой правкой.

## Что это
Личный трекер жизни для двух человек: **7 = Кирилл** (цвет коричневый `#7A4A2A`) и **4 = Даша** (тёмно-синий `#1E3557`). Тбилиси, Ваке. Интерфейс только на русском.

- PWA, чистый статический сайт: HTML + vanilla JS, **без сборки, без npm, без фреймворков**. Файлы открываются как есть.
- Хостинг: GitHub Pages, репозиторий `berning47-hub/pomoshnik-47` (публичный), ветка `main`.
  Адрес: https://berning47-hub.github.io/pomoshnik-47/
- Данные: `localStorage` (ключ `p47.v1`), синхронизация между телефонами через Supabase (`sync.js`).
- Вход: экран «Войти как Кирилл / Даша» + пароль (аккаунты Supabase `u7@pomoshnik47.app`, `u4@pomoshnik47.app`).

Порядок скриптов в `index.html` важен:
`private-data.js` (может отсутствовать) → ядро → `settings.js` → `food.js` → `money.js` → `sync.js` → `books.js` → `avatar.js` → `body.js` → `places.js`.

## Как устроен код
- Одно глобальное состояние `S`. После любого изменения данных: `save()` (пишет в localStorage и ставит синхронизацию), затем `render()`.
- HTML собирается строками в шаблонных литералах, обработчики вешаются в `bind()` через `data-*` атрибуты (`data-sec`, `data-act`...).
- **Новый раздел** делается отдельным файлом и сам себя регистрирует, не трогая ядро (образец: `body.js`, `places.js`, `books.js`):
  1. добавить пункт в `SECTIONS` (`['key','иконка','Название']`), если его там нет;
  2. обернуть функции ядра: `const _soon = soonView, _bind = bind, ...; soonView = k => k==='key' ? myView() : _soon(k);` (так же `modalView`, `bind`, `render`, `settingsPage`, `bindSettings`);
  3. зарегистрировать данные для синхронизации в `sync.js`-реестре:
     `ARR.<coll> = {get:()=>S.x, set:a=>{S.x=a;}}` — массив записей с `id`;
     `OBJ.<coll> = {get:()=>S.y}` — объект по ключам;
     `SINGLE.<coll> = {get:()=>S.z, set:d=>{S.z=d;}}` — один объект настроек;
  4. добавить `<script src="...">` в конец `index.html` и файл в `FILES` в `sw.js`.
- Новые поля в `S` инициализируй защитно (`S.x = S.x || []`), у старых пользователей их нет.
- Разделы ещё не готовые показывают заглушку из `SOON` (сейчас: «Еда», «Учёба»).

## Правила прав (обязательно)
- Каждый меняет **только свои** данные. Кирилл не может менять/удалять данные Даши и наоборот — во всех разделах.
- Чужое показывается только для чтения. Запись принадлежит автору (`owner` / `by`: `'7'`, `'4'` или `'both'`); текущий пользователь — `S.me`.
- Общие задачи (`owner:'both'`): каждый ставит свою отметку сам; задача готова, когда отметили оба.
- Образец проверки: `canEdit` в `index.html`.

## Дизайн
- Светло-коричневая тема (фон `#F6EFE6`), есть тёмная. Цвета только через CSS-переменные (`--bg`, `--card`, `--line`, ...), не хардкодить.
- Минимализм и практичность. Mobile-first: основное использование с телефона (нижняя навигация, крупные касания, без горизонтального скролла).
- Сначала минимальная рабочая версия раздела, потом полировка мобильного UX.
- Никакого автозаказа и автоматических действий во внешних сервисах: только ссылки (например, на магазин в Wolt).
- Уведомления только внутри приложения.

## Релиз
1. Внёс изменения → проверь в браузере (можно просто открыть `index.html` или `python -m http.server`).
2. **Подними версию кэша** в `sw.js` (`const CACHE = 'p47-vN'` → `N+1`), иначе телефоны покажут старую версию. Новый файл — добавь в `FILES`.
3. Коммит и push в `main` → GitHub Pages обновится сам за 1–2 минуты.
4. Перед коммитом проверь `git status`: `private-data.js` не должен попасть в коммит.

## Безопасность
- Никогда не коммить `private-data.js`, пароли, токены, `service_role` ключ Supabase.
- Publishable/anon ключ Supabase в `sync.js` публичный по задумке: данные закрыты RLS (доступ только двум аккаунтам, у `anon` прав нет, удаления нет — только `deleted=true`).
- Адрес дома не хранится в коде: задаётся на устройстве в «Местах».
- Внешние скрипты только с надёжных CDN с точной версией.
